## Systemtexte als brauchbare Arbeitsverträge schreiben

Leite einen Systemtext vom Zweck der Anwendung und ihren tatsächlichen Arbeitsbedingungen ab. Für eine kleine Programmierhilfe sind das etwa: eine passende Lösung für die gewünschte Sprache liefern, entscheidende fehlende Angaben klären, Erklärungen am Verständnisbedarf ausrichten und ausgeführte Prüfungen korrekt benennen. Diese Angaben ermöglichen sinnvolle Entscheidungen. Eine starre Pflicht, vor jeder kurzen Additionsfunktion erst einen langen Plan zu verfassen, würde den Nutzen häufig verkleinern. Ein festgelegter Ablauf ist dort sinnvoll, wo eine reale Abhängigkeit besteht, etwa erst eine Datei lesen und anschließend eine darauf bezogene Änderung erstellen.

Formuliere Ergebnisse und Grenzen konkret. „Hilf gut“ sagt wenig darüber, ob eine Erklärung, ein Codeblock oder eine Änderung in einem bestehenden Projekt gebraucht wird. „Du kannst in dieser Anwendung keinen Code ausführen; bezeichne eine statische Prüfung entsprechend“ beschreibt eine reale Einschränkung. Behaupte eine Fähigkeit erst, wenn die Anwendung sie tatsächlich anbietet. Umgekehrt sollte ein Arbeitsvertrag vorhandene Fähigkeiten so erklären, dass der Agent sie bei passenden Aufträgen sinnvoll nutzen kann. Ein Werkzeugkatalog ohne Zweck und Rückgabe ist dafür ebenso unzureichend wie eine Wunschliste ohne Werkzeuge.

Prüfe eine gewünschte Regel auf ihre Durchsetzungsebene. Eine Formulierung kann erklären, wann ein Zugriff angemessen ist. Ob ein bestimmter Account einen fremden Datensatz öffnen darf, muss der ausführende Dienst selbst prüfen. Wenn ein Toolaufruf den falschen Mandanten angibt, darf seine Berechtigung nicht allein davon abhängen, dass der Systemprompt das verboten hatte. Gleichzeitig muss nicht jede stilistische Entscheidung in eine technische Schranke gegossen werden. Antwortlänge, Reihenfolge der Erklärung und Wahl eines verständlichen Beispiels brauchen meist semantischen Spielraum.

Verbessere einen Arbeitsvertrag anhand beobachteter Fehlentscheidungen. Hat die Anwendung eine entscheidende Rückfrage ausgelassen, beschreibe, welche fehlende Information den Lösungsweg verändern würde. Hat sie unnötig angehalten, kläre, welche Routineentscheidungen bereits vom Auftrag umfasst sind. Hat sie einen nicht ausgeführten Test behauptet, verbinde Berichtsregeln mit den tatsächlich vorhandenen Ausführungsbelegen. Ergänze nicht nach jedem Einzelfall eine weitere isolierte Verbotszeile. Ein zusammenhängender Auftrag mit erkennbarem Ziel, relevanten Informationen, verfügbaren Fähigkeiten und einem passenden Ergebnismaßstab lässt sich leichter anwenden und prüfen. Die im Buch verwendete Bezeichnung für diesen Ansatz ist eine Benennung der Methode, kein eigener Nachweis ihrer Überlegenheit in jeder Aufgabe.
