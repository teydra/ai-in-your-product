## Transkripte in die Anwendung übernehmen

Bezeichne das kleine Objekt mit `text` und `language` als internes Beispielobjekt. Es zeigt, welche Information die Anwendung weiterverarbeiten möchte. Es behauptet kein universelles Antwortschema aller Transkriptionsdienste. Zeige bei einem echten Projekt, welche Anbieterfelder der Adapter gelesen hat und wie daraus die internen Felder entstehen. Ein Sprachcode kann ein erkannter Wert, eine vom Menschen gewählte Einstellung oder eine vom Programm ergänzte Vorgabe sein. Die Bedeutung muss zur Herkunft passen.

Entscheide, welche Zusatzinformation für die nächste Aufgabe erhalten bleiben muss. Für eine gewöhnliche Chatnachricht kann der bestätigte Text reichen. Untertitel brauchen Zeitbezug. Eine Korrektur an einer Aufnahme kann Zugriff auf das Originalsegment benötigen. Eine Sprecherzuordnung ist nur dann verwendbar, wenn der Dienst oder die Anwendung sie tatsächlich erzeugt und ihre Bedeutung bekannt ist. Der Übergang von reichhaltigen Audiodaten zu reinem Text verwirft Informationen; eine spätere Textanfrage kann diese nicht einfach zurückgewinnen.

Wenn diktierte und getippte Eingaben denselben String ergeben und ansonsten derselbe Kontext übergeben wird, kann das nachfolgende Modell daraus keine verlässliche Herkunft ableiten. Falls das Produkt die Eingabeart für einen konkreten Zweck braucht, kann es sie als eigenes Metadatum behalten. Ob dieses Metadatum auch zum Modell übertragen wird, ist eine separate Entscheidung. Eine Aufnahmekennung kann für die lokale Bearbeitung nötig sein, ohne Teil der Modellanfrage zu werden.

Beziehe Rückfragen auf erkennbare Folgen. Eine falsch erkannte Bestellnummer kann eine Suche zum falschen Datensatz führen. Eine sichtbare Korrekturmöglichkeit hilft hier unmittelbar. Ob zusätzlich bestätigt werden muss, hängt von der vorgesehenen Aktion und dem bereits bestehenden Bedienablauf ab. Füge nicht bei jeder Spracheingabe eine neue Freigabeschleife ein. Bei einem tatsächlich ausgeführten Bestell- oder Zahlungsvorgang muss die bestehende fachliche Prüfung der Aktion auch für die Spracheingabe gelten; der Erkennungsdienst ersetzt sie nicht.

## Originalsignale für die Aufgabe erhalten

Erkläre Multimodalität über die verfügbaren Eingaben. Eine Aufgabe kann neben Text ein Bild, eine Tonaufnahme oder zeitbezogene Mediendaten benötigen. Welche Eingaben ein konkretes Modell akzeptiert, entscheidet seine Schnittstelle. Das Wort „multimodal“ allein legt weder Dateiformat noch Ausgabeart fest. Ein Modell, das ein Bild beschreiben kann, muss keine bearbeitete Bilddatei erzeugen können; ein Modell mit Audioeingang muss nicht automatisch Audio ausgeben.

Ermittle zunächst die Information, die eine reine Textfassung verliert. Bei einer schlecht verständlichen Aufnahme kann der Originalton helfen, Lautalternativen zu beurteilen. Bei einem beschädigten Gegenstand braucht eine Frage nach sichtbaren Stellen das Bild. Eine vom Nutzer geschriebene Zusammenfassung kann dagegen genügen, wenn nur ihr Inhalt verarbeitet werden soll. Mehr Mediendaten sind nicht grundsätzlich eine bessere Eingabe: Entscheidend ist, ob sie Informationen für die konkrete Aufgabe enthalten und tatsächlich vom Modell verarbeitet werden können.

Halte Beobachtung und Schlussfolgerung getrennt. Aus einem Bild kann das Modell eine sichtbare Veränderung beschreiben; die Ursache oder eine nicht sichtbare Eigenschaft bleibt eine andere Behauptung. Ein Tonfall kann Hinweise liefern, aber eine vermeintlich sichere emotionale oder intentionale Deutung geht über eine Transkription hinaus. Erkläre bei einer Rückfrage, auf welchem verfügbaren Signal eine Aussage beruht und was damit noch nicht geklärt ist.

Für einen Vergleich zwischen spezialisiertem Speech-to-Text und einem multimodalen Modell verwende dieselben relevanten Aufnahmen und eine passende Bewertungsfrage. Die Aufgabe „wörtlich transkribieren“ ist anders als „den Sinn zusammenfassen“ oder „unklare Wörter zur Korrektur anbieten“. Lege fest, welche davon das Produkt benötigt. Ein ausdrucksstarker Kommentar zum Audio ist kein Nachweis genauerer Worterkennung. Umgekehrt können gute Alternativvorschläge eine nützliche Produktfunktion sein, auch wenn die reine Transkriptionsfehlerrate dadurch nicht sinkt.
