## JSON so erklären, dass Lesen genügt

Das Buch verspricht der Person, dass sie JSON lesen, aber nicht auswendig können muss. Halte dieses Versprechen. Erkläre die sechs Bausteine am Beispiel: Objekt in geschweiften Klammern, Feld aus Name und Wert, Text in Anführungszeichen, Zahl ohne Anführungszeichen, Wahrheitswert `true` oder `false`, Liste in eckigen Klammern und `null` als bewusst fehlender Wert. Verschachtelung entsteht, weil ein Wert selbst wieder Objekt oder Liste sein kann.

Führe Pfade als Werkzeug zum Zeigen ein: `geraet.zubehoer[0]` ist das erste Element der Liste `zubehoer` im Objekt `geraet`, und `content[0].text` ist der Text im ersten Inhaltsteil einer Anthropic-Antwort. Weise darauf hin, dass Listen ab null zählen und dass die Pfadschreibweise eine Konvention zum Benennen ist, kein Bestandteil von JSON selbst.

Mach außerdem den Unterschied zwischen eigenen Feldern und Anbieterfeldern sichtbar. In Leihregals eigenem Format darf Mara `geraet` oder `akku` schreiben und sollte Namen wählen, die ein Mensch in einem Jahr noch versteht. In einem Brief an einen Anbieter gelten dessen Namen. Ein zusätzlich erfundenes Feld wird nicht zur Funktion, nur weil es im JSON steht. Diese Unterscheidung verhindert mehr Fehler als jede Syntaxregel.

## Die drei Lesefragen für jeden Datenblock anwenden

Das Buch gibt der Person drei Fragen an die Hand: Wer hat dieses Format festgelegt? Wohin reist dieser Brief? Was passiert im Produkt mit jedem Feld? Nutze sie als Gliederung, wenn du einen unbekannten Block erklärst, ob aus einer Dokumentation, einer Fehlermeldung oder einem Log.

Die erste Frage trennt Anbieterformate, Formate anderer Dienste und eigene Formate. Davon hängt ab, ob ein Name geändert werden darf. Die zweite Frage ordnet den Block einer Strecke zu: Browser zu Server, Server zu Anbieter oder zurück. Derselbe Inhalt sieht auf jeder Strecke anders aus, und der API-Schlüssel darf nur auf der Strecke zum Anbieter auftauchen. Die dritte Frage verbindet jedes Feld mit Anzeige, Speicherung, Entscheidung oder bewusstem Ignorieren.

Kannst du eine der drei Fragen nicht beantworten, sage das und benenne, welche Information fehlt, zum Beispiel die Stelle im Code, an der der Block entsteht. Erfinde keine Herkunft, um die Erklärung abzurunden. Bei einem Feld ohne erkennbare Wirkung ist die ehrliche Antwort oft: Es wird derzeit nicht verwendet.
