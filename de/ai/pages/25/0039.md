## Die Briefe eines Produkts auseinanderhalten

In einem Produkt reisen mehrere Briefe. Bei Leihregals Erklärfeld sind es vier: Brief 1 vom Browser an den eigenen Server in Leihregals Format, etwa `{"begriff": "Phantomspeisung", "geraet": "M2"}`; Brief 2 vom Server an den Anbieter im Anbieterformat; Brief 3 als Antwort des Anbieters; Brief 4 vom Server an den Browser, wieder im eigenen Format. Innerhalb von Brief 2 und 3 reisen später Werkzeugbeschreibungen, Werkzeugaufrufe und strukturierte Antworten; das Buch nennt sie die Familie der Briefe im Brief.

Ordne jede Frage nach „dem JSON“ einer dieser Strecken zu. Ein Fehler beim Eingabefeld betrifft oft Brief 1, ein abgelehnter Aufruf Brief 2, eine leere Antwortblase vielleicht das Auslesen von Brief 3 oder das Format von Brief 4. Der API-Schlüssel wird erst auf dem Server für Brief 2 ergänzt und verlässt den Server nie Richtung Browser.

Bei einer Umsetzung halte die eigenen Formate klein und fachlich benannt. Der Browser braucht keine Anbieterfelder und keine Modellkennung. Der Server ist die Stelle, an der eigene Daten in den Anbieterbrief übersetzt, Antworten geprüft und für die Oberfläche aufbereitet werden. So bleibt ein späterer Anbieterwechsel auf den Server beschränkt.
