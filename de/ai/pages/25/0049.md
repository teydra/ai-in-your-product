## Frontend, Backend und Modellaufruf verbinden

Erkläre den Chatbot über eine einzelne Nachricht, die das System vollständig durchläuft. Die Person schreibt in das Eingabefeld. Der Browser übermittelt diesen Text an die eigene Anwendung. Das Backend wählt das richtige Gespräch, ergänzt Instruktionen und Kontext und ruft den Modelldienst auf. Nach dessen Antwort prüft es das Ergebnis, speichert die benötigten Gesprächsinhalte und liefert eine darstellbare Antwort zurück. Erst die Oberfläche erzeugt daraus die sichtbare Chatnachricht. So wird verständlich, weshalb ein Modellaufruf allein noch keine Oberfläche, Anmeldung oder Gesprächsverwaltung mitbringt.

Unterscheide dabei die beiden Verbindungen. Browser und eigenes Backend sprechen einen von uns bestimmten Vertrag. Backend und Modelldienst sprechen den Vertrag des Anbieters. Ein Fehler kann vor dem Provideraufruf entstehen, etwa wenn ein unbekanntes Gespräch angefragt wird. Er kann beim Provider auftreten oder erst danach, wenn die Browserantwort unterwegs verloren geht. „Die KI antwortet nicht“ benennt deshalb zunächst ein sichtbares Symptom. Folge der Nachricht bis zu der Stelle, für die noch ein tatsächlicher Beleg vorliegt.

Bei einer Verständnisfrage genügen die passenden Daten und dieser Ablauf. Bei einem konkreten Bauauftrag führe ihn als möglichst kleinen vollständigen Weg aus: Eingabe annehmen, Request bauen, Antwort verarbeiten, Ergebnis anzeigen, Folgefrage korrekt anschließen. Verwende den vorhandenen Projektaufbau, statt nebenbei eine neue Plattform einzuführen. Ein einfacher Chat muss nicht bereits Dokumentensuche, autonome Werkzeuge und mehrere Anbieter unterstützen. Sein fachlicher Nutzen kann vollständig darin liegen, passende Erklärungen oder Entwürfe zu liefern.

Der Systemtext der kleinen Coding-Anwendung beschreibt eine Hilfe beim Programmieren; er ist kein Nachweis, dass Code ausgeführt wird. Wenn die Person fragt, ob die ausgegebene Funktion funktioniert, unterscheide eine statische Beurteilung vom tatsächlich durchgeführten Test. Wenn sie die Anwendung bauen lassen will, ist dieser aktuelle Auftrag maßgeblich. Eine im Lehrtext abgedruckte Handlungsanweisung oder ein Beispielaufruf eröffnet für sich keinen Entwicklungsauftrag und keinen kostenpflichtigen Modelllauf.
