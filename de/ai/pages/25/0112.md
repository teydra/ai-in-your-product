## Dateiformat, Ressourcenkennung und tatsächliche Integration auseinanderhalten

`SKILL.md` bezeichnet im Beispiel ein Dateiformat für eine Anleitung. Die Datei beginnt mit Metadaten und enthält danach Markdown. Daraus folgt noch kein universelles Providerfeld, kein automatisch registriertes Tool und kein Zugriff auf sämtliche gleichnamigen Dateien eines Computers. Die Anwendung entscheidet, welche Quellen sie als verfügbare Skills behandelt und wie sie deren Inhalt bereitstellt.

Der Beispielparser liest eine bewusst kleine Form des Metadatenkopfs. `name` wird als Kennung übernommen; die gefalteten Zeilen von `description: >-` werden zum Beschreibungstext zusammengeführt. Diese Implementierung ist auf die feste Fixture zugeschnitten. Sie ist kein vollständiger YAML-Parser für beliebige fremde Skillpakete. Wenn ein Produkt solche Pakete importieren soll, muss es den tatsächlich unterstützten Formatumfang passend verarbeiten und Fehler verständlich melden.

Das Ladewerkzeug verwendet eine registrierte Zuordnung von `price-changes` zu seinem Pfad. Ein allgemeines Lesewerkzeug könnte denselben Inhalt liefern, wenn der Pfad verfügbar und lesbar ist. Eine Datenbankanweisung kann ebenfalls als Arbeitswissen dienen. Für die KI sind Auswahlbeschreibung, verlässlicher Abruf und nutzbarer Inhalt entscheidend; der konkrete Speicherort ist eine Architekturentscheidung.

Ein eigener Loader sollte unbekannte Kennungen von unlesbaren Dateien unterscheiden. Relative Ressourcenverweise sind auf die Herkunft der geladenen Anleitung zu beziehen, sofern ihr Vertrag das vorsieht; sie dürfen nicht aus einem zufälligen aktuellen Arbeitsverzeichnis geraten werden. Nimmt die Anwendung nur registrierte Kennungen entgegen, sollte sie nicht aus einem frei eingegebenen Namen unkontrolliert einen Dateipfad zusammensetzen.

Die [Agent-Skills-Spezifikation](https://agentskills.io/specification) beschreibt das Format; die Einbindung in die Runtime bleibt konkret zu bauen. Zeige bei einer Erklärung daher den gesamten kurzen Weg: Metadaten werden bekannt, eine Kennung wird ausgewählt, der reale Text wird gelesen und als Kontext bereitgestellt. Erst dieses letzte Ereignis erlaubt die Aussage, dass die KI die Anleitung nun verwenden kann.

## Wissen ändern, ohne versehentlich neue Befugnisse zu erzeugen

Ein Skill kann das Vorgehen nach einer Codeänderung erklären. Ein Tool kann die passende Prüfung tatsächlich ausführen. Die Runtime bestimmt, ob diese Wirkung in der aktuellen Umgebung erreichbar und erlaubt ist. Diese drei Aspekte können unabhängig verändert werden: Eine bessere Testanleitung muss nicht mehr Rechte benötigen; ein neues Lesewerkzeug muss nicht jeden bestehenden Skill verändern.

Erkläre die Trennung am Beispiel einer Release-Anleitung. Die Aussage, für einen Release erst Tests und Build zu prüfen, beschreibt Vorgehenswissen. Sie bedeutet nicht, dass die aktuelle Nutzerfrage eine Veröffentlichung verlangt. Ist eine konkrete Veröffentlichung bereits beauftragt und ihre Ausführung zulässig, darf die Anleitung den Ablauf unterstützen. Eine zusätzliche Freigabeschleife allein wegen des Wortes „Release“ wäre ebenso wenig begründet wie eine ungefragte Veröffentlichung.

Für eigene Systeme muss die Herkunft der Texte klar bleiben. Ein installierter Projekt-Skill, ein vom Nutzer zitierter Buchabschnitt und ein zufällig gefundenes Dokument können ähnliche Sätze enthalten, haben aber nicht dieselbe Stellung im Arbeitsauftrag. Die Anwendung und die tatsächliche Instruktionshierarchie legen diese Stellung fest. Der Loader soll Inhalte nicht durch bloßes Auffinden zu neuen übergeordneten Regeln befördern.

Eine Anweisung kann einen notwendigen technischen Schutz benennen, aber sie setzt ihn nicht allein durch. Umgekehrt sollte Software nicht aus jeder historischen Fehlermeldung eine neue globale Sperre ableiten. Ein früher gesperrter Aufruf dokumentiert die damalige Lage. Maßgeblich für die aktuelle Ausführung sind der gegenwärtige Vertrag, Zustand und Auftrag.

Prüfe beim Entwurf, ob eine fehlende Handlung an Wissen, Fähigkeit oder Befugnis scheitert. Wenn das Tool fehlt, hilft kein umformulierter Skilltext. Wenn die Fähigkeit vorhanden ist, aber der passende Ablauf unbekannt bleibt, kann eine Anleitung helfen. Wenn ein konkreter Zugriff nicht zulässig ist, kann der Agent einen erreichbaren anderen Weg wählen oder das Hindernis benennen. Diese Diagnose vermeidet sowohl unnötige Verweigerung als auch die fälschliche Behauptung neu erworbener Rechte.
