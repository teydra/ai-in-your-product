Das Modell kann nun statt einer Textantwort einen Tool Call erzeugen. Bei unserem Function Tool heißt dessen Typ in dieser API function_call. Aus der output-Liste der Antwort betrachten wir die entscheidenden Felder:

~~~text
{
  "type": "function_call",
  "name": "run_command",
  "call_id": "call_01",
  "arguments":
    "{\"command\":\"rg --files\"}"
}
~~~

Art der Ausgabe. Eine Funktion wird angefordert.

Werkzeugname. Welche angebotene Fähigkeit?

Aufrufkennung. Welches Ergebnis gehört zu diesem Aufruf?

Eingaben. Was soll das Werkzeug bekommen?

arguments enthält eine Zeichenkette, in der wiederum JSON steht: ein Brief im Brief. Die inneren Anführungszeichen sind deshalb als \\" geschrieben. Die Runtime liest diese Zeichenkette aus und erhält das Argumentobjekt:

~~~text
{
  "command": "rg --files"
}
~~~

Das ist derselbe Inhalt in ausgelesener Form, kein anderes API-Format. command ist der Feldname; rg --files ist der Text, der an unser Werkzeug gehen soll.
