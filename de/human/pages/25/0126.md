Anfrage 1 · vollständiger JSON-Body · Fortsetzung (2/2)

~~~text
{
    "role": "user",
    "content": "Hotelwissen: Beispielhotel, Check-in ab 15 Uhr. Wissenskatalog: kb_hours = Öffnungszeiten."
  },
  {"role": "user", "content": "Ist das Hotel am Wochenende geöffnet?"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "load_knowledge",
      "description": "Lädt Wissensinhalt.",
      "parameters": {
        "type": "object",
        "properties": {
          "knowledge_id": {"type": "string", "enum": ["kb_hours"]}
        },
        "required": ["knowledge_id"],
        "additionalProperties": false
      },
      "strict": true
    }
  }],
  "response_format": {"type": "json_object"}
}
~~~

Kontext vom Server. Hauptwissen und Wissenskatalog als Daten.

Besucherfrage. Die Rolle ordnet die Nachricht ein; sie ist keine ID.

Fähigkeit. Name und Argumente des Werkzeugs, das das Modell anfordern kann.

Antwortformat. JSON-Modus für den abschließenden Antworttext.

## Woher kommen die zusätzlichen Angaben?

Der Besucher schreibt nur die letzte Nachricht. Die Anwendung ergänzt die drei vorangehenden. Auch der Hotelkontext trägt die Rolle user, stammt aber vom Server.

Hauptwissen ist hinterlegter Text. Im Request stehen Hotelname und Check-in. Von kb_hours kennt das Modell erst
