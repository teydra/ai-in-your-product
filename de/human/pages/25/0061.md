## Wenn es schiefgeht, und es geht schief

Jetzt gehen wir Fehler durch, die bei echten Anbieteraufrufen passieren. Die folgende Fehlerfolge ist ein Lehrbeispiel; der Demomodus erzeugt sie nicht.

Wir schicken unserem Chatbot die erste Nachricht:

User: Schreib mir eine JavaScript-Funktion, die zwei Zahlen addiert.

Es kommt keine Modellantwort. Der Anbieter meldet:

401 · authentication_error

Der Anbieter akzeptiert den API-Schlüssel nicht. Im Backend ist noch ein widerrufener Schlüssel eingetragen. Wir ersetzen ihn und starten das Backend neu. Bei 403 · permission_error müssten wir dagegen prüfen, ob wir das ausgewählte Modell mit diesem Schlüssel verwenden dürfen.

Beim nächsten Versuch meldet die API fehlendes Guthaben. Also prüfen wir die Abrechnung des API-Kontos. Ein bezahltes Chat-Abo und die API werden getrennt abgerechnet; im Chat-Abo steckt kein API-Guthaben. Nach dem Aufladen senden wir die Nachricht erneut.

Assistant: function add(a, b) { return a + b; }

Jetzt antwortet der Chatbot. Auch auf „Mach die Funktion stattdessen in Python“ bekommen wir in diesem Beispiellauf die passende Funktion.
