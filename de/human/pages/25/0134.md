## Wenn weiteres Wissen oder andere Fähigkeiten nötig werden

Der gezeigte Request bietet nur eine Wissensquelle an. Ein größerer Bot stellt stattdessen mehrere knappe Beschreibungen bereit und lädt Details bei Bedarf:

~~~text
Zunächst im Modellkontext | Nach dem Laden
Wissen: Kennung und Zweck
einer Hotelquelle
Ihr gelesener Text als Tool Output
Skill: Name und Zweck einer
Arbeitsanleitung
Die Anweisungen dieses Skills
Tool: Katalogeintrag einer
Fähigkeit
Die Tool-Beschreibung für den
nächsten Modellaufruf
~~~

Das Modell muss zwischen einer Beschreibung und dem verfügbaren Inhalt unterscheiden. Ein Katalogeintrag liefert noch keine Zimmerverfügbarkeit. Ein Skill kann erklären, wann eine Übergabe an einen Menschen sinnvoll ist; die tatsächlichen technischen Berechtigungen stellt die Runtime bereit. Teydra kann dafür Werkzeuge wie load_knowledge, load_skill, search_tools und load_tool anbieten. Die Namen beschreiben Fähigkeiten dieses Produkts, keine automatisch vorhandenen Funktionen jeder Modell-API.

Eine Prüfung aktueller Zimmerverfügbarkeit würde auf denselben Loop zurückgreifen: Das Modell fordert den Aufruf an, die Runtime fragt das Buchungssystem ab und übergibt das tatsächliche Ergebnis. Geöffnet, verfügbar und gebucht sind
