Damit das Modell diese Rückgabe verwenden kann, schickt die Runtime sie in den nächsten Modellaufruf. Die Antwort mit unserem Tool Call hatte die API-Kennung resp_01. Über previous_response_id schließen wir an genau diese Antwort an; diesmal verwaltet also der Anbieter den Verlauf für uns, eine der beiden Möglichkeiten aus Kapitel 3. Die kurzen Kennungen stehen beispielhaft für die tatsächlich gelieferten Werte. Der vollständige nächste Request:

price-demo → OpenAI · nächster Request mit dem Werkzeugergebnis (1/2)

~~~text
{
  "model": "<modellname>",
  "instructions": "Arbeite im ausgewählten Projekt. Lies betroffene Dateien vor Änderungen. Nutze reale Werkzeugergebnisse. Führe passende Tests aus. Berichte genau, was geändert und geprüft wurde.",
  "previous_response_id": "resp_01",
  "tools": [
    {
      "type": "function",
      "name": "run_command",
      "description": "Führt einen Befehl im ausgewählten Projekt aus und liefert stdout, stderr und exit_code.",
      "parameters": {
        "type": "object",
        "properties": {"command": {"type": "string"}},
        "required": ["command"],
        "additionalProperties": false
      },
      "strict": true
    }
  ],
~~~

Anschluss an die Antwort mit dem Tool Call.

Werkzeuge gehen erneut mit; die Kennung ersetzt sie nicht.
